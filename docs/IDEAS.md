# 普及のアイデアメモ

日本の Meshtastic には既に本気の取り組みがある。preset の違う拠点を MQTT でつなぐ
ptp mesh（katsumoss さん）、地震・台風速報を流す JPEQ（Y1215 さん）。
技術的には見事だが、届いているのは「既にノードを持っている人」だけだ。
入口が「無線機を買い、preset / PSK / MQTT を設定する」ままでは広がらない。
訴求力の弱さはここにある。以下は、その入口を広げるための案のメモ（未決定）。

## 1. 相手がいなくても価値がある端末

チャットは相手がいないと始まらない。だが時計・掲示板・警報表示は一人でも価値がある。

- 部屋時計や電子ペーパー掲示板に、地震・台風などの警報表示を載せる
- 「誰かと話せる」より先に「置いてあるだけで役に立つ」を成立させる
- チャット相手は後から自然に増える（置いてある端末同士が挨拶を始める）

## 2. 部屋時計がゲートウェイを担う

ゲートウェイは特別な機械（母艦のような開発機）ではなく、どの家にもある
部屋時計が担うのが理想。ROOM 時計は既に WiFi で天気を取りに行っている。
同じ口で警報フィード（JPEQ / ptp の MQTT）を受ければよい。

- 警報は自分の画面に出し、ESP-NOW で家中の家族端末にも中継する（最後の10メートル）
- 家族端末はネットもアカウントも不要のまま、警報が「届く」
- いつも点いている・いつも目に入る・設定不要 — ゲートウェイの条件を日常のモノが満たす
- katsumoss さん / Y1215 さんの仕組みを、家庭の入口に翻訳する形
- 母艦（PocketTerm35）は開発・実験用でよい

## 3. 既存コミュニティへの相乗りブリッジ

新しい網を空っぽから始めるのではなく、既にある網とつなぐ。

- ゲートウェイ役の時計が ptp/commons の MQTT を購読し、公開の会話と警報を家庭内 CoT に映す
- CoT 端末を買った（渡された）その日から「誰かが見える」状態になる
- preset を翻訳する ptp の発想を、プロトコル翻訳（Meshtastic ⇔ CoT）に広げる
- ※ コミュニティ側への相談とマナーの確認が前提

## 4. 製品単位は「2台1組」

ptp のサイトも書いている通り、初めての通信相手は結局もう一台の自分のデバイスになる。

- 最初からペアで渡す／売る（親機・子機ではなく、名前と顔の付いた2台）
- 設定済み・名前入りで箱を開けたらすぐ話せる状態にする
- 「ノードを買う」ではなく「話せる相手ごと渡す」

## 5. 画面にはノードではなく人を出す

ノードID、SNR、ホップ数は愛好家の言葉。一般の人には「誰がいるか」だけが要る。

- 相手は顔アイコンと名前で表示する（Comic Chat の方向）
- 電波の状態は色と表情で伝え、数字は設定の奥にしまう
- 操作はボタンの長押しまで。キーボードは上級者向けに残す

## 6. 訴求は日常から入る

防災を看板にすると、非常袋の中で眠る道具になる。

- 看板は日常の便利さ（時計、掲示板、家族の連絡）
- 「ネットが無くても話せる」は性質として静かに語る
- 毎日触られている端末だけが、いざという日に生きている
