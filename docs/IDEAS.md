# 普及のアイデアメモ

日本の Meshtastic には既に本気の取り組みがある。preset の違う拠点を MQTT でつなぐ
ptp mesh（katsumoss さん）、地震・台風速報を流す JPEQ（Y1215 さん）。
技術的には見事だが、届いているのは「既にノードを持っている人」だけだ。
入口が「無線機を買い、preset / PSK / MQTT を設定する」ままでは広がらない。
訴求力の弱さはここにある。以下は、その入口を広げるための案のメモ（未決定）。

## 1. 相手がいなくても価値がある端末

チャットは相手がいないと始まらない。だが時計・掲示板・警報表示は一人でも価値がある。

- 部屋時計や電子ペーパー掲示板に、地震・台風などの警報表示を載せる
- 「誰かと話せる」より先に「置いてあるだけで役に立つ」を成立させる
- チャット相手は後から自然に増える（置いてある端末同士が挨拶を始める）

## 2. 部屋時計がゲートウェイを担う

ゲートウェイは特別な機械（母艦のような開発機）ではなく、どの家にもある
部屋時計が担うのが理想。ROOM 時計は既に WiFi で天気を取りに行っている。
同じ口で警報フィード（JPEQ / ptp の MQTT）を受ければよい。

- 警報は自分の画面に出し、ESP-NOW で家中の家族端末にも中継する（最後の10メートル）
- 家族端末はネットもアカウントも不要のまま、警報が「届く」
- いつも点いている・いつも目に入る・設定不要 — ゲートウェイの条件を日常のモノが満たす
- katsumoss さん / Y1215 さんの仕組みを、家庭の入口に翻訳する形
- 母艦（PocketTerm35）は開発・実験用でよい
- ※ 今の CYD（ESP32 無印）では力不足: フラッシュは既に 96%、PSRAM なし、
  WiFi 常時接続 + MQTT + ESP-NOW 中継を同時に担う余力がない。
  後継の時計は ESP32-S3 級 + PSRAM が条件になる
- 後継の時計の最優先要件は温湿度・気圧が測れること（部屋時計の存在理由）。
  センサーは内蔵か I2C 拡張で必須
- PaperMono はセンサー拡張ができないので時計役にはならない（電子書籍リーダー役のまま）
- 後継機の条件: スレート形状で 3〜5 インチ（邪魔にならないこと）、
  センサー付きか後付け可能、頭脳と無線に余力があること
- 候補は M5Stack Tab5 に収束（「Room to Summit」の台）。
  決め手は技適: CrowPanel Advance はモジュールの認証はあるが、製品に
  技適シールが付かない — シール無し T-Deck で自分が引いた線と同じグレーになる。
  Tab5 は国内販売の完成品で表示が製品に付く。グレーゼロを取る
- 代償は ESP32-P4 + C6（hosted 無線）で S3 系ファームと別プラットフォームなこと。
  ESP-NOW が hosted で動くかの検証（3ステップ）が、この役割全体の関門になる
- フォールバック確定: Tab5 が駄目なら CrowPanel Advance 5.0" S3 を買う
- 他の候補（2026-10-31 調査）: 技適縛りでは極端に減り、結局 WROOM 頼みになる。
  SenseCAP Indicator（Seeed、3.95" 完成品スレート、スイッチサイエンス販売）は
  形は良いが気圧センサーが無く、センサー類が RP2040 側にぶら下がる変則構成。
  Waveshare ESP32-S3-Touch-LCD-4.3B-BOX はケース付きで CrowPanel と同格（WROOM 頼み）

## 3. 既存コミュニティへの相乗りブリッジ

新しい網を空っぽから始めるのではなく、既にある網とつなぐ。

- ゲートウェイ役の時計が ptp/commons の MQTT を購読し、公開の会話と警報を家庭内 CoT に映す
- CoT 端末を買った（渡された）その日から「誰かが見える」状態になる
- preset を翻訳する ptp の発想を、プロトコル翻訳（Meshtastic ⇔ CoT）に広げる
- ※ コミュニティ側への相談とマナーの確認が前提

## 4. 製品単位は「2台1組」

ptp のサイトも書いている通り、初めての通信相手は結局もう一台の自分のデバイスになる。

- 最初からペアで渡す／売る（親機・子機ではなく、名前と顔の付いた2台）
- 設定済み・名前入りで箱を開けたらすぐ話せる状態にする
- 「ノードを買う」ではなく「話せる相手ごと渡す」

## 5. 画面にはノードではなく人を出す

ノードID、SNR、ホップ数は愛好家の言葉。一般の人には「誰がいるか」だけが要る。

- 相手は顔アイコンと名前で表示する（Comic Chat の方向）
- 電波の状態は色と表情で伝え、数字は設定の奥にしまう
- 操作はボタンの長押しまで。キーボードは上級者向けに残す

## 6. 訴求は日常から入る

防災を看板にすると、非常袋の中で眠る道具になる。

- 看板は日常の便利さ（時計、掲示板、家族の連絡）
- 「ネットが無くても話せる」は性質として静かに語る
- 毎日触られている端末だけが、いざという日に生きている

## 7. 家族ネットワークの標準構成

家族1単位のネットワークは、M5Stack 製品だけで組める。

- 据え置き: Tab5 — 部屋時計 + ゲートウェイ + 大画面
- 持ち歩き: PaperMono（読書）か CoreS3（音楽）
- AI チャットボット: StickS3
- 音声は全機共通の互換軸、文字は Stick 以外の全機で書ける
- PaperMono はスピーカー無しでよい: 入力はマイク、相手の音声は文字に
  変換されて画面に出る（読む機械なので、返事は文字が自然）。
  音声→文字の変換役は網の中の1台（母艦やホームサーバー）が担う
- そして、その文字が Comic Chat（顔 + 吹き出し）で出てきたら最高。
  音声入力と漫画表現の合流点がここにある。白黒の漫画表現は電子ペーパーにも合う
- 家族ネットワーク同士のゲートウェイは Unit C6L が担う

他社製品を混ぜなくても家族単位の網が成立し、網同士も自前の橋でつながる。

## 8. コミュニティ間ゲートウェイ（C6L）

Meshtastic は全部を LoRa だけで回そうとした。CoT は分業する。

- コミュニティ内の会話: ESP-NOW（帯域に余裕があり音声も使える、範囲は家〜拠点）
- コミュニティ間の連絡: ゲートウェイ同士だけが LoRa で話す
- 橋は Unit C6L: ESP-NOW ⇄ LoRa の翻訳役。据え置き・常時給電でよい

橋を渡るもの / 渡らないもの:

- 渡る: グループのテキスト、SOS、位置の要約
- 渡らない: 音声（LoRa のエアタイムを食いすぎる）、HELLO などのプレゼンス

LoRa 側の作法:

- 告示49号のパターン（LBT、0.4 秒バースト、360 秒/時）に収める
- メッセージ ID で重複排除し、橋同士のループを防ぐ
- 出元のコミュニティ名と発言者名を付けて届ける

新しい家族（コミュニティ）が増えるたびにゲートウェイが 1 つ増え、網が伸びる。
中継専用ノードを撒くより、伸び方が自然になる。

運び手は LoRa に限らない。届けば何でもよい — 将来は HaLow でも、衛星でも。
だからゲートウェイの作りは「橋の論理（宛先・重複排除・蓄積）」と
「運び手（無線）」を分けておき、運び手を取り替えられるようにする。
今日の実物は LoRa（手元にあり、制度も分かっている）というだけの話。
