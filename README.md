# ENZ CoT — Chat of Things

```
CYD> おはよう、気圧下がってきた
M5Core2> おはよう。こっちは電池100%
T-Deck (L)> 山の上からでも聞こえる?
```

**ネットがなくても、話せる。**
すべてのガジェットが、チャットできる。
No cloud. No account. Just chat.

IoT が「モノがネットにつながる」なら、CoT は「モノ同士がおしゃべりする」。
ENZ CoT は、ESP-NOW と LoRa で直接会話する自作デバイスのシリーズです。
サーバーもアカウントも要りません。電源を入れたら、もう会話が始まっています。

## なぜ作るのか

ガジェットは、たいてい「まだ使える」のに終わります。ファームウェアの
更新から取り残されて終わる。サービスが終了して終わる。電池が死んで
終わる。本当の寿命である物理的な破壊以外で終わるのは、作り手の都合です。

ENZ CoT は、その 3 つの死を最初から拒否する設計です。ファームウェアは
自分で書ける。サーバーを持たない。電池は交換できる汎用セル。
詳しくは [設計思想](docs/PHILOSOPHY.md) に書きました。

## コンセプト

軸はひとつです。**誰もがスマホを持っている時代に、劣化スマホはいらない。**
ENZ CoT が提案するのは、スマホの代わりではなく「2台目の専用機」。
全部入りを目指さず、スマホが苦手な仕事だけを引き受けます。

どの機種も作りは同じで、**「軸になる機能 + チャット」**。
M5Core2 は小型音楽プレイヤーのオマケにチャット、CYD は部屋時計の
オマケにチャット、T-Deck は主役がチャットそのものの
オフラインチャットマシーン。チャットはオマケですが、家族が増えるほど
豪華になるオマケです。新機種の作法は「まず何の専用機か決める。
チャットは必ず付く」。

- **参加条件は「話せること」** — 時計でも、キーボード端末でも、画面のない
  ボタンでも。会話に参加できれば、シリーズの一員です
- **共通語は1つ** — 全機種が [CoT プロトコル](docs/PROTOCOL.md)
  (223 バイトの共通パケット)で話します。新機種はまず「話せる」ことから作ります
- **日本語で話す** — かな入力と SKK 変換まで、全機種の共通仕様です
- **専用機であること** — 常時表示の時計と気圧グラフ、物理キーボード、
  物理ボタン、電池を気にせず置きっぱなしにできること。
  「得意なことだけ、ちゃんとやる」が2台目の実用性です

| 機種 | フォルダ | 役割 | 状態 |
|---|---|---|---|
| CYD (ESP32-2432S028) | [firmware/cyd](firmware/cyd) | 部屋時計、のオマケにチャット(時計・センサー・天気。屋外版/屋内版) | 実機確認済み |
| M5Core2 | [firmware/m5core2](firmware/m5core2) | 小型音楽プレイヤー、のオマケにチャット(Bluetooth音声出力つき) | 実機確認済み |
| LILYGO T-Deck | [firmware/tdeck](firmware/tdeck) | オフラインチャットマシーン(ESP-NOW + LoRa、物理キーボード) | 実機確認済み(Phase 1) |
| RP2350-USB (Tenstar) | [firmware/rp2350](firmware/rp2350) | USBボタン(F13)。シリーズの入力デバイス基盤 | コンパイル検証済み |

今後の予定: Elecrow CrowPanel Advance(Room to Summit:部屋では
センサー時計兼フォトフレーム、山ではフィールド端末)、Heltec Wireless
Paper(電子ペーパー掲示板、手持ち在庫から)、LILYGO T-Deck Plus
(GPS で位置を喋る係、手持ち在庫から)、M5Stick(ボイスレコーダーの
オマケにチャット)、M5Stack PaperMono(候補:電子書籍リーダーの
オマケにチャット。LoRa 付きは通常版のみ)、Stamp C3 無線コールボタン、
RP2350 + ESP32-C3 ペア(ENZ BASE)、音声 PTT(CoT プロトコルの
type 3 を予約済み)。
Wi-Fi HaLow(IEEE 802.11ah)への対応も構想中。T-Deck(無線番長)に
SPI/SDIO の外付けモジュールとして追加する想定で、日本の割当て・
制度整備が固まるのを待って着手する。IP がそのまま通るため、
CoT の長距離・高速な伝送路として位置づける。
手持ちの Meshtastic 機材(Unit C6L ×2、Wio Tracker L1 Pro、Cardputer ADV、
T-Echo Lite、XIAO nRF52 / ESP32 + Wio-SX1262 キット ×各3)も順次
CoT ノード化する。ESP32 系は ESP-NOW + LoRa のフルノードに、nRF52 系は
LoRa 専用ノードとして T-Deck のブリッジ経由で家族に合流する想定。

実験と失敗の記録は [docs/EXPERIMENTS.md](docs/EXPERIMENTS.md) に
残します。失敗も資産として公開し、分からないことは「知りたいこと」
として明記します。見てくれた人が答えを持っているかもしれないので。

## 設計方針

- 対応機種では、[bmorcelli Launcher](https://github.com/bmorcelli/Launcher)
  から起動できる .bin での配布を原則とする(絶対の縛りではない。
  Launcher 経由ならアップデートを OTA で流せるのが理由)
- リリースの命名規則: `ENZ_<機種>_v<版数>` で、タグ・タイトル・
  .bin のファイル名をすべて同じにする(例: ENZ_TDECK_v14 /
  ENZ_TDECK_v14.bin)。誰が見ても機種と版が一目で分かるように
- 工場出荷時の初期値に個人情報は入れない(位置情報は東京都庁、表示名は JohnDoe)
- 新しい機種は、まず既存機種とチャット互換であることから作る
- 未知のパケットタイプは無視する(将来拡張で旧ファームを壊さない)

## 電波法について

- 本プロジェクトで使う無線機器は、日本の技術基準適合証明(技適)を
  受けた機種・モジュールを前提とします
- LoRa は ARIB STD-T108 に準拠して運用します(920MHz 帯、送信出力
  13dBm 以下、送信前のキャリアセンス、送信時間制限の順守。
  詳細は [docs/PROTOCOL.md](docs/PROTOCOL.md))
- 日本国内で技適未取得機器を用いる実験を行う場合は、総務省の
  [技適未取得機器を用いた実験等の特例制度](https://www.tele.soumu.go.jp/j/sys/others/exp-sp/)
  に基づき、事前に届出を行います
